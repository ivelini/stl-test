# Решения (ADR)

Журнал архитектурных решений: «почему система устроена так». Правила ведения — глобальное правило `adr.md`.

- Пишем при решении с развилкой, которое иначе переоткроют или переспорят.
- Полстраницы, четыре поля: Контекст / Решение / Почему / Последствия.
- Отменённое решение не удаляется: статус `Superseded`, изменённое решение — новый ADR.
- Не пишем сюда: детали реализации (расписания, размеры батчей, имена команд) и решения без развилки.
